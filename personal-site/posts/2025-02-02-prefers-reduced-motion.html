动效要有礼貌：prefers-reduced-motion 实践笔记

2025 年 2 月 2 日 · 可访问性 约 6 分钟

我曾经为一个落地页做了一个很得意的首屏动画：背景缓慢放大、卡片依次浮起、 标题逐字淡入。上线第二天，一位同事告诉我他打开页面时会头晕， 所以他把系统的"减少动态效果"打开了——但我的页面完全无视这个设置。

谁会真的被影响

这不是少数人的洁癖。前庭功能障碍、偏头痛、内耳疾病患者对大面积位移和缩放非常敏感， 部分人甚至会因为一个视差滚动而恶心半天。此外还有一类很朴素的场景： 有人在晃动的公交上看你的页面，有人在低电量模式下希望少耗一点电。

一行媒体查询解决 90% 的问题

操作系统层面早就提供了开关：iOS 和 macOS 的"减弱动态效果"、Windows 的 "显示动画"、Android 的"移除动画"。浏览器会把它暴露给 CSS 和 JS。 我在这套站点的样式表末尾放了这么一段： 

@media (prefers-reduced-motion: reduce) {
  *,
  *::before,
  *::after {
    animation-duration: 0.001ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.001ms !important;
    scroll-behavior: auto !important;
  }
}

把时长压到接近零而不是直接 display: none，是因为有些组件依赖 transitionend 或 animationend 事件来收拾状态， 直接取消动画会让它们卡住。压时长既去掉了"动"，又保留了事件的触发。

只对三个属性做动画

另一件同样重要的事是别乱做动画。transform、opacity 和 box-shadow 之外的属性，动画起来几乎都会触发重排或重绘， 在手机上会立刻掉帧。最常见的错误是动 width、height、 top 和 left——它们看起来"只是移动一下"， 实际上每一帧都在重新计算整个布局。

  • 要位移就动 transform: translateY()，不要动 top。
  • 要变大就动 transform: scale()——但注意，这套站点刻意不用缩放做 hover，因为缩放会让人误以为元素被选中了。
  • 要变颜色就动 color 或 background-color，这两个是安全的例外。
  • 过渡时长控制在 0.2 到 0.3 秒之间。超过 0.5 秒的过渡在交互上会被感知为"卡"。

别只盯着 hover 动效

同一个偏好也应该用在 JavaScript 里。凡是自动播放的轮播、无限循环的呼吸效果、 滚动触发的视差，都应该先问一句 matchMedia("(prefers-reduced-motion: reduce)")， 命中就别启动。纯 CSS 的动画交给上面那段媒体查询就够了， 但用 JS 手动控制的循环动画不会被 CSS 拦住，需要你主动处理。

把动效理解成"给用户的礼物"而不是"产品的一部分"，取舍就容易多了： 礼物可以不送，但绝不能让人难受。

这套站点里保留了三个动效：按钮上浮 2 像素、卡片上浮 4 像素、头像 4 秒一次的 1.02 倍呼吸。它们都很轻微，而且一旦系统开了"减少动态"，就全部静止。
