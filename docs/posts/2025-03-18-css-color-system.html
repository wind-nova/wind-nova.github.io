用 CSS 变量搭一套会长大的配色系统

2025 年 3 月 18 日 · CSS 约 8 分钟

我做过的第一个网站的样式表是这样的：见到一个好看的颜色就写一个十六进制值， 同一个蓝色在文件里出现了十一次，每次都略有不同。三个月后我想把主色调深一点， 于是用查找替换改坏了半个站点。

现在这个站点的颜色全部收在文件顶部的两段变量里。改配色从"一次高风险手术" 变成了"改三行然后刷新"。

从三个颜色开始

不要一开始就列出三十个变量。先只定三个：背景、正文文字、主色。 剩下的颜色都从这三个里派生出来——次要文字是正文色的降饱和版本， 边框是背景色的加深版本。这样配色天然是和谐的，因为你只做了三个决定。

这套站点现在长这样，两套主题各写一遍同样的名字，只是取值不同：

:root {
  --color-bg:      #fdfbf7;
  --color-text:    #3d3a38;
  --color-primary: #7eb8c9;
}

[data-theme="dark"] {
  --color-bg:      #1f1d1b;
  --color-text:    #ede8e0;
  --color-primary: #8fc9d9;
}

命名比取值重要

变量名里不要出现具体颜色。--color-blue 是坏名字， 因为半年后你可能把它改成绿色，那时候整个代码库都在说谎。 用用途命名：--color-primary、--color-border、 --color-text-secondary。

  • 坏名字：--light-gray、--big-blue、--color-2
  • 好名字：--color-bg、--color-card、--color-border
  • 判断标准：把值换成完全不同的颜色，名字是否依然成立

深色主题不是把颜色反过来

最省事的做法是把浅色主题的每个值取反，结果是刺眼的纯黑背景配纯白文字， 看五分钟眼睛就累了。深色主题应该重新做一次三个决定：

  • 背景不要用 #000，用带一点暖调的深灰，比如 #1f1d1b。
  • 正文不要用 #fff，稍微压暗一点，比如 #ede8e0，对比度依然远超标线但没那么扎眼。
  • 主色要提亮一档。同一个蓝在浅色背景上正好，在深色背景上会显得发暗。
  • 阴影要换成深的、透明度更高的黑，浅色主题那套暖灰阴影在深色下完全看不见。

改配色时只改变量，不要在组件样式里写死颜色。一旦某个按钮写了 #7eb8c9， 它就会成为下一次改配色时唯一没跟着变的地方。

一张可以照抄的清单

如果你要重做一套配色，可以按这个顺序来，每一步都能立刻在浏览器里看到结果：

  1. 定背景、正文、主色三个值。
  2. 补出次要文字色和边框色。
  3. 补出卡片色（通常就是浅色主题下的纯白、深色主题下的背景加亮一档）。
  4. 写阴影变量，浅色用低透明度的暖灰，深色用高透明度的黑。
  5. 派生两三个"主色柔化版"：十分之一透明度的底色、用于 focus 圆环的半透明色。
  6. 把全站的颜色换成引用变量，然后搜一遍十六进制值——理想情况下，它们只应该出现在文件顶部。

最后一条是检验这套系统有没有真正落地的唯一标准：如果样式表中间还能搜到 # 开头的颜色值，说明还有一个组件没被收编。
